# 先交可用部分，再处理局部异常

## 默认动作

遇到异常先看影响哪些记录、字段或步骤，而不是先终止整个任务。
只做足以确认影响范围的轻量检查，不要求证明异常完全无偏才探索。
探索用的临时子集不是对正式分析样本的永久排除，也不替作者批准发表结论。

| 情况 | 现在做什么 | 留下什么 |
|---|---|---|
| 10,000个样本有1个ID未匹配，其余可唯一匹配，异常不涉及关键对照/配对 | 先用9,999个完成可用的探索结果；未匹配者保留待处理，不补ID | 原始总数10,000、实际9,999、待核对1及原因 |
| 可选字段缺失，不影响该步骤 | 保留记录，字段标unknown，继续 | 字段级缺失；不要整行删除 |
| 单文件损坏或单个批任务失败 | 保留失败状态，继续独立任务，避免无止境重试 | 成功/失败数、失败ID或路径；后续可单独重试 |
| 一个唯一对照或配对成员无法确认 | 暂停依赖该对象的比较；继续可独立解释的QC、描述或其他比较 | 受影响的比较及缺什么；不伪造替代对照 |
| 重复key局限于可识别的少数ID，其余可确认一对一 | 隔离所有歧义key的相关记录，继续唯一映射部分；不擅自择一去重 | 歧义记录与实际有效数；已知配对/设计依赖仍单独判断 |
| join整体基数异常、无法划定歧义范围，或疑似整列单位/ID错位 | 停止该不可信join或统计；继续输入汇总/定位等不受影响工作 | 具体疑点；不能以比例很小为理由忽略全局错误 |

这些是示例，不是“错误低于某百分比就接受”的阈值。既不因1条异常
阻断9,999条，也不以9,999条存在就推断唯一关键样本无关紧要。
若项目明确要求完整样本集，保留该正式门槛；仍可交付明确区分的候选部分。

## 最小记录与输出

- 在现有日志/manifest或一张待核对表记录：对象ID、异常原因、临时处理、
  涉及的步骤和可恢复入口。小任务不额外建立管理体系。
- 不用静默inner join或宽泛异常捕获隐藏损失；按该操作说明输入行/唯一ID数、
  成功匹配数、未处理数和重复key情况。相关统计用实际有效分母。
- 保留正常部分与异常清单；异常记录可修复后增量重跑，不覆盖原始输入。
- 先展示用户要看的候选表/图/答案，再用一句话说清范围。例如：
  “先用能匹配的9,999个样本得到这版结果，另外1个ID暂未对上，已保留待核对。”
- 只有观察结果与失败原因，不把未运行写成功，也不把部分结果写全量完成。

## 何时回补

方向值得继续、异常可能影响判断，或准备进入正式分析/论文时，再核对
未解决对象、缺失是否集中于某组、样本排除和必要的稳健性检查。
正式结果固定实际样本集、统计定义与排除理由；无法支持的结论不晋升。
待核对不等于无限延期：在已有任务记录留下一项下一步即可，不阻止当前交付。
