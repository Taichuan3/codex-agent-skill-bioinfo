# 可编辑科研演示文稿

## 核心问题

如何把已有材料做成可继续人工编辑的PPTX，并保持文字、原图、版式和来源可核查？

## 边界

- 编辑已有文件时保留原件，默认另存；只读请求不重生成幻灯片。
- 使用当前已安装且适合任务的执行工具；本模块拥有内容/交付要求，不替代用户明确指定的插件后端。
- 科研图保留原图比例、图号、轴、数值和限定语；美化不得生成替代数据。需要重新分析或重绘时转 `publication-plotting`。
- 已有完整图像页仍是位图，不假称文字或图表可编辑；明确需要图片式整页设计时转 `codex-ppt`。
- 用户模板、字体、页码和输出路径优先；下述上游参考的强制样式只是默认设计配方。

## 工作流

1. 从已有文件/说明确定交付物：读取、修改或新建；仅询问真正缺失的材料。不为读一页PPT扫描环境。
2. 已有模板先提取内容并查看版式；结构化XML编辑按 `references/editing.md`，保持关系、媒体和notes一致。
3. 新建时按 `references/creation-workflow.md` 组织同步 `createSlide(pres, theme)` 模块、compile入口和源图目录。
4. 按需读取 `references/design-system.md`（主题/字体）、`references/slide-types.md`（页面布局）、`references/pptxgenjs.md`（API）。只保留必要的页型与设计约束，尺寸采用一种一致布局。
5. 执行前按 `references/portable-runtime.md` 确认已用后端的最小依赖；不自动全局npm安装，不把node_modules、字体、凭据或运行环境写入Skill。
6. 按 `references/pitfalls.md` 检查内容，再渲染逐页查看截断、重叠、比例与中文字体。文字提取成功不能代替视觉检查；无法渲染时明确未验证视觉质量。
7. 最终交付PPTX及可编辑源码/素材入口，说明页数、可编辑范围和未解决问题；按 `project-state-maintenance` 更新受影响项目入口，日期只作运行历史。

## 失败与交付

缺少源文件、模板、字体或必需依赖时明确具体缺口，完成不受影响的部分。损坏XML或无法打开的PPTX不标记完成；不覆盖原稿以尝试修复。保留具体输入和生成命令；没有实质变化不重写GUIDE。

默认先给文件和简短说明，不输出长设计审查报告。参考文件来自MIT许可上游的适配，完整许可见 `LICENSE`，来源与本地改动见仓库的第三方来源说明。
