# Submission Checklist

## Blocking

- Every main claim maps to figure/table/source data/citation.
- Main text numbers match figures, legends, methods, and supplementary tables.
- Methods include data source, reference version, software version, key parameters, filtering rules, and statistics.
- Source data files exist for main figure panels.
- Code or notebooks can regenerate core tables and figures.
- Data/Code Availability statements are specific.
- Reviewer attack list has been written and blocking attacks are answered by evidence, validation, caveat or downgraded wording.
- Exploration, confirmation and validation results are not mixed in the manuscript narrative.

## Important

- Abstract does not overstate exploratory results.
- Introduction does not promise a mechanism that Results cannot prove.
- Discussion separates supported conclusions from hypotheses.
- Figure legends include n, filtering status, statistical test, and caveat where needed.
- Supplementary tables are named and discoverable.

## Reviewer attack list

| Attack area | Question | Blocking if unanswered? |
|---|---|---|
| Central claim | Can the main claim be stated in one sentence and mapped to figures/tables? | Yes |
| Figure logic | Does every main figure advance the central claim rather than add decorative analysis? | Often |
| Alternative explanations | Are batch effects, sample bias, confounders and method artifacts addressed? | Often |
| Validation | Is the strongest claim supported by independent data, orthogonal method or appropriate downgrade? | Often |
| Reproducibility | Can the key result be regenerated from code, data, parameters and environment? | Yes |
| Data/code availability | Are repository/accession/source data/code/environment details specific and truthful? | Yes |
| Methods | Are software versions, thresholds, random seeds, filtering rules and statistics described? | Yes |
| Journal fit | Is the advance broad enough for the intended journal level? | Sometimes |
